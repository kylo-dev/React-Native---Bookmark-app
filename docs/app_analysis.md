# Bookmark App UI/UX 및 로직 분석 리뷰

현재 `bookmark-app`의 코드를 분석한 결과, 전반적인 UI 레이아웃과 화면 전환(Navigation) 뼈대는 잘 구현되어 있으나, **데이터의 상태 관리와 실제 동작 로직, 그리고 예외 상황에 대한 처리(UI/UX)** 가 누락되어 있는 형태(정적 프로토타입)입니다.

앱의 사용자 흐름(User Flow) 관점에서 발견된 로직상의 문제점과 추가되어야 할 기능들을 정리했습니다.

---

## 1. 구현된 로직상 문제점 (수정 필요 사항)

### 1-1. 정적(Static) 데이터 사용 및 상태 관리 부재
*   **문제점:** `index.tsx`, `[id].tsx`, `sentence.tsx` 등 주요 화면에서 `BOOKS`, `SENTENCES`, `TIMELINE_EVENTS` 등의 하드코딩된 더미 데이터를 사용하고 있습니다. 
*   **영향:** `RegisterBookScreen`이나 `NewRecordScreen`에서 "Save" 버튼을 눌러도 실제 데이터가 앱 내부나 서버에 저장되지 않고 반영되지 않습니다.
*   **해결 방안:** Redux, Zustand 등의 전역 상태 관리 라이브러리를 도입하거나 React Context API, 로컬 스토리지(AsyncStorage 등), 또는 실제 백엔드 API와의 연동 로직 구현이 필수적입니다.

### 1-2. 필터링 및 검색 로직 미구현 (홈 화면)
*   **문제점:** `index.tsx`에서 탭(All Books, Reading, Finished, Cancelled)을 클릭하면 활성화 스타일만 변경될 뿐, 화면에 노출되는 리스트 자체가 필터링되지 않습니다. 또한 상단 검색(Search) 버튼도 터치 이벤트 로직(`onPress`)이 없습니다.
*   **해결 방안:** `activeFilter` 상태값에 따라 `BOOKS` 배열을 `filter()`하는 로직을 `FlatList`의 `data` 속성에 바인딩해야 합니다.

### 1-3. 화면 이동 간 Context(파라미터) 유실
*   **문제점:** 라우팅 시 파라미터 전달 로직이 누락된 곳이 있습니다. 예를 들어, `[id].tsx` (책 상세)에서 `new-record.tsx` (새 기록)로 넘어갈 때 어떤 책에 대한 기록인지에 대한 정보(`bookId`)가 전달되지 않아, "상실의 시대"와 같은 하드코딩된 책 정보가 노출됩니다.
*   **해결 방안:** `router.push({ pathname: '/book/new-record', params: { bookId: id } })` 형태로 문맥(Context)을 전달하고, 전달받은 화면에서 해당 책 데이터를 불러와 렌더링하도록 수정해야 합니다.

### 1-4. 폼 유효성 검사(Validation) 부재
*   **문제점:** `register.tsx`(책 등록), `new-record.tsx`(문장 기록), `sentence.tsx`(생각 추가) 등의 입력 화면에서, 내용을 비워둔 채 저장(Save/Send) 버튼을 눌러도 아무런 경고(Validation) 없이 넘어갈 수 있습니다.
*   **해결 방안:** 제목, 저자, 내용 등 필수 입력값이 비어있을 경우 저장 버튼 비활성화 또는 Toast/Alert 메시지를 통한 경고 로직이 필요합니다.

## 2. 앱 사용자 흐름상 추가되어야 하는 기능 (Missing Features)

### 2-1. 데이터가 없을 때의 화면 (Empty States)
*   **필요성:** 앱을 처음 설치한 사용자나, 아직 읽고 있는 책이 없는 카테고리를 눌렀을 때 화면이 텅 비어 보이면 (또는 더미 데이터만 보이면) 사용자 경험이 크게 저하됩니다.
*   **추가 기능:** "아직 등록된 책이 없습니다. + 버튼을 눌러 새로운 책을 추가해보세요!" 형태의 Empty State UI 및 일러스트레이션이 홈 화면(`index.tsx`)과 상세 화면(`[id].tsx`)에 필요합니다.

### 2-2. 편집 및 삭제(Edit & Delete) 기능
*   **필요성:** 사용자가 본인이 입력한 정보(책 제목 오타, 상태 변경, 남긴 문장이나 생각 수정 등)를 정정하거나 삭제할 수 있는 장치가 없습니다.
*   **추가 기능:** 
    *   **책 상태 변경/편집:** 책 상세(`[id].tsx`) 화면 내 상태 배지('Reading', 'Finished' 등)를 직접 클릭하여 상태 변경. 우측 상단 `more-horiz` 메뉴에서는 [책 정보 수정, 책 삭제]를 제공.
    *   **기록 편집:** 저장된 문장(`sentence.tsx`) 내에서 오타 수정 및 삭제 기능.

### 2-3. 기기 네이티브 기능 연동 (카메라 / 갤러리)
*   **필요성:** `register.tsx`에 "Upload Cover", `new-record.tsx`에 "Scan Text" 버튼이 UI로만 존재합니다.
*   **추가 기능:** 
    *   `expo-image-picker`를 활용한 기기 사진 갤러리 접근 및 카메라 촬영 로직 연동 (책 표지 등록).
    *   Vision API를 활용한 OCR(광학 문자 인식) 기능 연동 (책 페이지를 사진 찍어 텍스트로 바로 변환).

### 2-4. 진행도(Progress) 및 통계 기능
*   **변경 사항:** `register.tsx`에서 총 페이지 개수를 더 이상 입력받지 않음.
*   **앱 방향성:** 기존의 전체 페이지 대비 현재 읽은 페이지(%)를 계산하는 방식 대신, 사용자가 기록한 문장의 수, 남긴 코멘트의 수, 완독한 책의 개수 등을 활용한 통계 기능으로 전환하는 것을 고려.

### 2-5. 사용자 피드백 (Loading & Toast)
*   **필요성:** 데이터를 저장("Save to Library")하거나 업로드할 때 진행 상태를 알 수 없어 사용자가 멈춘 것으로 오해할 수 있습니다.
*   **추가 기능:** ActivityIndicator(로딩 스피너) 노출 및 성공적으로 저장되었을 때 하단에서 올라오는 Toast/Snackbar 메시지 기능 추가.
